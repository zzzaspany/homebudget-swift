# Building, toolchains and the Xcode project

## Xcode cannot build the web client

**Symptom.** `WebClient` fails to build from Xcode with an error about the WebAssembly target.

**Cause.** Apple's clang, shipped inside Xcode, has no WebAssembly backend, and JavaScriptKit has a
C target that needs one.

**Fix.** Two toolchains, for two jobs. Xcode builds and tests everything for macOS; a swift.org
toolchain with the WASM SDK builds the client. The Makefile sets `DEVELOPER_DIR` per target and
unsets it for the WebAssembly build, so no `sudo xcode-select --switch` is needed. `make doctor`
reports on both. Use `make web`, not Xcode, for the client.

*Hit during Phase 0.*

## Tests do not run under the Command Line Tools

**Symptom.** `swift test` fails to find XCTest or Swift Testing.

**Cause.** Neither ships with the Command Line Tools; they come with Xcode.

**Fix.** `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`, or just use `make test`,
which points `DEVELOPER_DIR` at Xcode itself.

## Builds crawl and the indexer fails on rename

**Symptom.** Checkouts take minutes, and the index store errors on rename.

**Cause.** The repository lives on an SMB share (`/Volumes/Multimedia`), mounted by a LaunchAgent.
SwiftPM's build directory and index store both assume a local filesystem's rename semantics.

**Fix.** Every Makefile target passes `--disable-index-store` and keeps its build directory under
`~/Library/Caches/homebudget-swift`. A clone on local disk needs neither, but this one is not.

Related: **the share can unmount mid-session.** A shell whose working directory disappeared silently
resets to a parent — which once created `project.yml` outside the repository entirely. Use absolute
paths in shell commands rather than relying on an inherited working directory.

*Hit repeatedly.*

## `UILaunchScreen` in build settings has no effect

**Symptom.** The iOS app runs letterboxed, in the compatibility mode iOS uses for apps that predate
modern screen sizes, despite `INFOPLIST_KEY_UILaunchScreen` being set.

**Cause.** `INFOPLIST_KEY_*` build settings are only merged into a *generated* `Info.plist`. This
target supplies its own file, so they are ignored.

**Fix.** Put it in `info.properties` in `project.yml`, which writes into the supplied plist:

```yaml
info:
  path: Sources/Info.plist
  properties:
    UILaunchScreen: {}
```

*Hit 2026-09-07.*

## The Xcode project

Generated by XcodeGen from `Packages/HomeBudgetiOS/project.yml`, and gitignored. Edit the YAML and
run `xcodegen`; never edit the `.xcodeproj`. The alternative — committing the project file — was
considered and rejected: a `.pbxproj` diff is unreadable and merges badly, and there is nothing in
it here that the YAML cannot express.
